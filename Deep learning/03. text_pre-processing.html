Foundation

Why Pre-Processing?

Computers don't understand raw text — they only understand numbers. Raw text also contains a huge amount of noise: punctuation, capital letters, irrelevant words, and different forms of the same word. All of this confuses ML models.

Think of it this way: if you feed a model "Running", "running", and "RUNNING" — it treats them as 3 completely different things. Pre-processing fixes all of that.

STEP 01

Text Cleaning Always Used

Removing everything that adds zero value — HTML tags, URLs, special characters, numbers, emojis, extra whitespace. These carry no semantic meaning and create noise.

STEP 02

Lowercasing Traditional Only

Makes all text uniform. Without it, a model treats "Apple", "APPLE", "apple" as 3 completely separate words even though they're identical.

Input:
"The Quick Brown Fox Jumps Over The Lazy DOG"

After Lowercasing:
"the quick brown fox jumps over the lazy dog"
⚠️
For modern models like BERT, skip this step. BERT's own tokenizer handles casing — forcibly lowercasing can actually hurt performance because it loses information (e.g., "US" the country vs "us" the pronoun).
✂️
STEP 03

Tokenization Always Used

Models can't process a full sentence as one blob. Tokenization splits text into discrete units (tokens) so the model can process each piece individually.

3a. Word Tokenization
Input: "the cat sat on the mat"
Output: ["the", "cat", "sat", "on", "the", "mat"]
3b. Sentence Tokenization
Input: "I love NLP. It is powerful. Models learn from text."
Output:
["I love NLP.",
"It is powerful.",
"Models learn from text."]
3c. Character Tokenization

Used in character-level RNNs (text generation models)

Input: "cat"
Output: ["c", "a", "t"]
3d. Subword Tokenization (BPE)

Used in BERT, GPT. Splits rare words into common subword pieces — handles out-of-vocabulary words brilliantly.

Input: "unhappiness"
Output: ["un", "happiness"]

Input: "tokenization"
Output: ["token", "ization"]
🗑️
STEP 04

Stop Word Removal Mostly Avoided Now

Common words like "is", "the", "a", "and", "in" appear in almost every sentence and don't help the model differentiate topics. Removing them reduces noise and speeds up processing.

Input tokens:
["the", "cat", "is", "sitting", "on", "a", "mat", "in", "the", "room"]

Stop words list:
["the", "is", "on", "a", "in"]

After Removal:
["cat", "sitting", "mat", "room"]

// Meaning preserved: "cat sitting mat room" — 5 tokens removed
⚠️
Don't remove stop words blindly! For sentiment analysis, the word "not" is technically a stop word — but removing it turns "not good" into "good", completely flipping the meaning. Modern models like BERT handle this automatically without removal.
✂️
STEP 05

Stemming Legacy / Interviews

Cuts words down to their root form by chopping off suffixes using simple rules (no dictionary). Maps "running", "runs", "runner" all to "run" so the model sees one concept.

OriginalStemReal Word?
runningrun✅ Yes
happinesshappi❌ No
studiesstudi❌ No
connectionconnect✅ Yes
beautifulbeauti❌ No
fliesfli❌ No
Input:
"The studies show that running improves happiness"

After Stemming (Porter Stemmer):
["studi", "show", "run", "improv", "happi"]
❌
Stemming produces non-real words like "happi", "studi". It's fast but crude. Lemmatization is almost always preferred over stemming when accuracy matters.
📖
STEP 06

Lemmatization Traditional Projects

Reduces a word to its true dictionary base form (lemma) using vocabulary and grammar rules. Much smarter than stemming — always produces real words, handles irregular forms.

OriginalStemming ❌Lemmatization ✅
runningrunrun
betterbettergood
studiesstudistudy
am / is / aream / is / arbe
wentwentgo
fliesflifly
Input:
"He was running and studies showed he is better"

After Lemmatization:
["he", "be", "run", "and", "study", "show", "he", "be", "good"]

// "was" → "be", "better" → "good", "went" → "go" — all real words!
🔢
STEP 07

Encoding / Vectorization Core Step

The most critical step for RNNs. Converts text tokens into numbers (vectors) that the model can mathematically process. Multiple methods exist, each with trade-offs.

7a. Integer Encoding

Assign a unique integer to each word in the vocabulary.

Vocabulary:
{ "the":1, "cat":2, "sat":3, "on":4, "mat":5, "dog":6, "ran":7, "away":8 }

Sentence: "the cat sat on mat"
Encoded: [1, 2, 3, 4, 5]
7b. One-Hot Encoding

Each word becomes a vector of 0s with a single 1 at its index position.

Vocab: { cat:0, sat:1, on:2, mat:3, the:4 } (size=5)

cat [1, 0, 0, 0, 0]
sat [0, 1, 0, 0, 0]
on [0, 0, 1, 0, 0]
mat [0, 0, 0, 1, 0]
the [0, 0, 0, 0, 1]
❌
If vocab = 50,000 words → each vector is 50,000 long, mostly zeros. Extremely memory-heavy. Also no semantic relationship between words.
7c. Bag of Words (BoW)

Represent a sentence as word counts across the full vocabulary.

Vocabulary order: [cat, sat, mat, on, the, dog]

Sentence 1: "the cat sat on the mat"
BoW: [1, 1, 1, 1, 2, 0]

Sentence 2: "the dog sat on the mat"
BoW: [0, 1, 1, 1, 2, 1]
❌
Loses word order completely. "cat ate dog" and "dog ate cat" produce identical BoW representations.
7d. TF-IDF

Gives higher weight to words that are important in one document but rare across all documents. Smarter than BoW.

TF(word, doc) = count of word in doc / total words in doc
IDF(word) = log( total docs / docs containing word )
TF-IDF = TF × IDF
Higher score = more important word for that specific document
Doc 1: "cat sat on mat" (4 words)
Doc 2: "cat ran away" (3 words)

// "cat" appears in BOTH docs:
TF("cat", Doc1) = 1/4 = 0.25
IDF("cat") = log(2/2) = 0.0
TF-IDF("cat") = 0.25 × 0 = 0.0 ← not important

// "mat" appears in Doc1 ONLY:
TF("mat", Doc1) = 1/4 = 0.25
IDF("mat") = log(2/1) = 0.693
TF-IDF("mat") = 0.25 × 0.693 = 0.173 ← important!
7e. Word Embeddings (Word2Vec / GloVe)
⭐
The gold standard for RNNs. Each word becomes a dense vector of real numbers where similar words have similar vectors — captures semantic meaning.
// Similar words cluster together in vector space
king → [ 0.50, 0.32, -0.12, 0.89, ...]
queen → [ 0.48, 0.35, -0.11, 0.91, ...] ← close to king
cat → [-0.20, 0.10, 0.75, -0.30, ...]
dog → [-0.18, 0.12, 0.71, -0.28, ...] ← close to cat

// Famous arithmetic relationship:
king - man + woman ≈ queen
📐
STEP 08

Padding & Sequence Standardization Always Used

RNNs process batches of sequences. All sequences in a batch must be the same length. Padding adds 0s to shorter sequences to match the longest one.

Tokenized sentences (different lengths):
Sentence 1: [2, 5, 3] ← length 3
Sentence 2: [1, 7, 4, 8, 2] ← length 5
Sentence 3: [6, 3] ← length 2

// Pad to max_length = 5 with zeros (pre-padding):
Sentence 1: [0, 0, 2, 5, 3] ← padded
Sentence 2: [1, 7, 4, 8, 2] ← unchanged
Sentence 3: [0, 0, 0, 6, 3] ← padded

// Now all are length 5 → can batch together ✅
💡
Most frameworks (PyTorch, Keras) handle padding automatically. You also use a masking layer to tell the model "ignore the 0s — they're just padding, not real data."

Industry Reality Check

What Actually Happens in 2024-25

The traditional pipeline above is foundational knowledge — but real industry projects often look different.

✗ Mostly Dead / Avoided

  • Stemming (produces non-real words)
  • Stop Word Removal (BERT needs context)
  • Bag of Words for deep learning
  • Lowercasing before BERT
  • Manual vocabulary building

✓ Industry Standard Today

  • Text Cleaning (always)
  • HuggingFace AutoTokenizer
  • BPE / WordPiece subword tokenization
  • Padding + Truncation (auto)
  • Pretrained embeddings (BERT, GPT)
// Real-world code in 2024 (most of the pipeline is this simple):

from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")

encoded = tokenizer(
    "Running!! He was RUNNING faster 😊",
    padding=True,
    truncation=True,
    return_tensors="pt"
)

// Cleaning, tokenizing, encoding, padding → all done in one line
// The model handles everything else internally
🎯
The takeaway: Traditional preprocessing = important for interviews, concepts, and classical ML. In production deep learning, AutoTokenizer.from_pretrained() does almost everything. The fundamentals still matter because they explain why the tools work the way they do.
